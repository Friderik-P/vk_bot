# Как внести вклад в проект VK-GigaChat Bot

Спасибо, что хотите помочь улучшить этого бота! Ниже описаны простые правила, чтобы ваш вклад был принят быстро.

## Куда обращаться

- **Нашли баг?** Создайте Issue с меткой `bug`. Обязательно укажите:
  - Шаги для воспроизведения.
  - Ожидаемое поведение и фактическое.
  - Версию Python и ОС (если это важно).
- **Хотите добавить фичу?** Сначала создайте Issue с меткой `enhancement`, чтобы обсудить идею. Это сэкономит время на написание кода, который может не подойти по архитектуре.
- **Готовы исправить баг или добавить фичу?** Делайте Pull Request (PR).

## Как запустить проект локально

Чтобы протестировать изменения, вам нужно настроить окружение:

1. Создайте виртуальное окружение:
    ```bash
    python -m venv venv
    ```
2. Активируйте его:
    - Windows: `venv\Scripts\activate`
    - macOS/Linux: `source venv/bin/activate`
3. Установите зависимости:
    ```bash
    pip install -r requirements.txt
    ```
4. Настройте переменные окружения:
    Создайте файл `.env` в корне проекта (он не должен попасть в git!) и добавьте туда:
    ```env
    VK_API_TOKEN=ваш_токен_группы
    VK_GROUP_ID=id_группы
    GIGACHAT_AUTH_KEY=Bearer ваш_ключ_GigaChat
    ADMIN_IDS=000000000,000000000
    SERVER_NAME=MyVKBot
    ```
    > ⚠️ **Важно:** Никогда не коммитьте реальные токены в репозиторий. Файл `.env` уже добавлен в `.gitignore`. Файл `admins.yaml` создаётся автоматически при запуске и тоже игнорируется.

5. Запустите бота:
    ```bash
    python main.py
    ```

## Правила оформления Pull Request

Чтобы ревью прошло быстро, соблюдайте эти правила:

- **Название ветки:** Используйте префиксы, чтобы сразу было понятно, что внутри:
  - `feat/add-logging` — новая функциональность.
  - `fix/handle-timeout` — исправление ошибки.
  - `docs/update-readme` — правки документации.
- **Коммиты:** Делайте атомарные коммиты (один коммит = одно логическое изменение).
- **Сообщение коммита:** Используйте формат Conventional Commits:
  ```text
  feat: добавить обработку ошибок GigaChat API
  fix: исправить падение бота при пустом сообщении
  docs: описать фильтры в README
  ```
- **Проверки перед PR:**
  ```bash
  black . --check
  flake8 src/
  mypy src/
  pytest
  ```

## Чего мы не принимаем

- Коммиты с секретами. Любые файлы, содержащие реальные токены, ключи или пароли, будут отклонены.
- Гигантские PR. Если вы меняете 10 файлов сразу, лучше разбить на несколько маленьких PR. Так проще проверить изменения.
- Изменения, ломающие обратную совместимость, без предварительного обсуждения в Issue.

## Как связаться с автором

Если у вас есть вопросы, которые не подходят под формат Issue, вы можете написать мне в Telegram (ссылка в профиле GitHub) или оставить комментарий в любом открытом Issue.

## Архитектура проекта

```
vk_bot/
├── src/
│   ├── __init__.py         # Публичный интерфейс пакета src
│   ├── config.py           # Чтение и валидация .env
│   ├── prompts.py          # Промпты, заглушки, параметры моделей
│   ├── chat.py             # Логика запросов к GigaChat
│   ├── server.py           # Long Poll, маршрутизация, антиспам, админ-команды
│   ├── admins.py           # Хранение и управление администраторами
│   ├── db/                 # SQLite: пользователи, история, спам, баны
│   ├── filters/            # 18+ и контекстный фильтры, нормализация текста
│   ├── handlers/           # Обработчики сообщений и callback
│   ├── keyboards/          # VK клавиатуры
│   ├── services/           # Рассылка, health-check, GigaChat клиент
│   └── scheduler/          # Планировщик: рассылка, очистка, health-check
```

### Где что менять

- **Новая команда бота** — `src/handlers/message.py`
- **Новая inline-кнопка** — `src/handlers/callback.py`
- **Новый фильтр** — `src/filters/`
- **Новый сервис** — `src/services/`
- **Изменение рассылки** — `src/services/broadcaster.py` и `src/scheduler/constants.py`
- **Изменение клавиатуры** — `src/keyboards/`
